# Architecture

Product context, constraints and stack: see `CLAUDE.md`. This file covers only how the code is organized. It's intentionally thin until the prototype (tasks T1–T6 in `docs/done.md`) has validated the TTS pipeline. Expect it to change.

## TTS pipeline

```
text ──► espeak-ng (phonemizer, built into sherpa-onnx) ──► IPA phonemes
     ──► tokens.txt (phoneme → integer ID)
     ──► model.onnx (Piper VITS net, run by onnxruntime inside sherpa-onnx)
     ──► Float32 PCM samples (22050 Hz for imre) ──► WAV file ──► audio player
```

App code makes one call: `OfflineTts.generate(text:, sid: 0, speed:)` → `GeneratedAudio{samples, sampleRate}`.
Voice files per voice (from sherpa-onnx's converted Piper releases):

```
vits-piper-hu_HU-imre-medium/
  hu_HU-imre-medium.onnx      # the net (~60 MB)
  tokens.txt
  espeak-ng-data/             # pronunciation rules, many small files
```

### Android gotcha: real file paths
Native code (sherpa-onnx/espeak-ng) needs real filesystem paths. Voices are downloaded and extracted into `getApplicationSupportDirectory()/voices/` (see `VoiceInstaller`); nothing is read from Flutter assets. Use `flutter-examples/tts` in https://github.com/k2-fsa/sherpa-onnx as the reference for exact API names. The Dart API has quirks (e.g. the parameter really is spelled `maxNumSenetences`).

### Threading
`generate()` is a synchronous FFI call and blocks the isolate it runs on. `PiperEngine` therefore spawns a long-lived background isolate that owns the `OfflineTts` (FFI pointers can't cross isolates): it loads the model, then receives text and returns WAV paths. Requests are handled in order, so one sent mid-load waits for the load. `dispose()` makes the isolate free the model and exit; switching voices = dispose the old engine, create a new one. `SystemEngine` is already async (platform channel).

Rules:
- Android only (`flutter create --platforms android`). No iOS work yet.
- **Voice model files are never committed or bundled.** Installed at runtime into `<appSupport>/voices/<id>/`, with one shared `<appSupport>/voices/espeak-ng-data/`.
- Keep dependencies minimal. Approved: `sherpa_onnx`, `path_provider`, `audioplayers`, `flutter_localizations`, `intl`, `flutter_tts`, `shared_preferences`, `http`, `archive`, `crypto`, `package_info_plus`, `drift`, `drift_flutter`, `record` (BSD-3-Clause, for message banking; credit it in About), `flutter_secure_storage` (BSD-3-Clause, for the ElevenLabs key; credit it in About) (dev: `drift_dev`, `build_runner`). Ask before adding others.
- UI strings in Hungarian. Code, comments and docs in English.
- Hungarian-first, not Hungarian-only. In the prototype, hardcoded strings are fine. After it, all UI strings move to Flutter's standard `gen-l10n` (ARB files, `hu` as the template locale). Never hardcode language-specific assumptions in logic. Language-specific things include preloaded phrases, the voice list and the alarm list's sentences, so treat them as per-locale data.

## Decided later (not in prototype)
Licenses/About screen. State management: plain `setState` + drift `watch` streams; add a package only if that gets painful.

## Speaking (decided 2026-11-02)
- One **Mondom** button, no separate "Ismétlés". `Speaker.speak(text)` remembers the last `(voice id, normalized text)` → WAV path; the same key replays the WAV from the start without synthesizing, a new key synthesizes and deletes the previous WAV. Normalization: trim + collapse inner whitespace. This is "last utterance" only, not an audio cache (see `docs/TODO.md`).
- The free-text field keeps its text after speaking (so Mondom again = repeat) and has a ✕ to clear it. Older phrases are reachable through history.
- Sentence-row taps go through the same `Speaker.speak`, so tapping a row twice replays instantly.

## Storage (decided 2026-11-02)
SQLite via **drift** (typed tables/queries, migrations, reactive `watch` queries so e.g. a `said` change greys out a row without refresh code). Small settings (selected voice, last used list) stay in `shared_preferences`. The voice catalog stays JSON (read-only, hand-parsed; use `json_serializable` if more JSON types appear).

Tables (schema v1; v2 adds `seedLanguage`, v3 adds `color`, v4 adds `soundKey` + `alarm`, v5 adds `recordingGenerated`):
- `sentence_lists`: `id` PK, `title`, `kind` (`everyday | conversation | history`), `pinned` bool, `position` int, `seedKey` nullable, `seedLanguage` nullable (schema v2: the seed file the list came from; null for user lists and history), `color` nullable (palette key, schema v3), `createdAt`. Unique `(seedLanguage, seedKey)`, so the same seed list can exist once per language.
- `sentences`: `id` PK, `listId` FK (cascade delete), `text`, `position` int, `said` bool (default false), `recordingPath` nullable (message banking), `recordingGenerated` bool (default false, schema v5: the recording was generated with ElevenLabs, see "Message banking"), `soundKey` nullable (built-in sound played instead of TTS, schema v4), `alarm` bool (default false, schema v4; see "Alarm"), `seedKey` nullable (unique per list), `spokenAt` nullable (history ordering), `createdAt`.
- `app_meta`: key/value. `seeded` = `1` once the first seed was inserted (so deleting every seed list later doesn't trigger seeding again). Schema v1 had `seedLanguage` here; v2 moves it onto the lists.
- Dart naming: the `sentences.text` column is the getter `body` (`text` clashes with drift's `Table.text()`), so `Sentence.body`.
- Exactly one `history` list; it can't be deleted or renamed, its title is localized via ARB at display time. History is newest first by `position`: a new row gets `min(position) - 1` (negative values are fine), so moving to the top never shifts other rows.
- Moving a sentence to another list drops its `seedKey` (it left its seed list); copies never have one. Copy and move keep `soundKey`, `alarm` and `recordingPath`.
- Generated code (`database.g.dart`) is committed. Regenerate after changing tables: `dart run build_runner build --delete-conflicting-outputs`.

Seed data: `assets/seed/<lang>.json` (also has a top-level `historyTitle`, copied onto the history list when that language becomes the speech language; empty title = UI-language fallback); once inserted, they're ordinary rows the user can edit or delete. Changing the phone language later doesn't touch the DB.

**Speech language (decided 2026-11-03)** = the selected voice's language (`Voice.language`). For "Android alapértelmezett" it is the language of the picker row it was chosen from (id `system-<lang>`; the default row is the UI language). The UI follows the phone, but **sentence content follows the speech language**, because default sentences in a language the voice can't pronounce are useless (e.g. a Hungarian user with a German phone who picks Imre under "Más nyelvek").
- `onCreate` only creates the history list. The seed is inserted **when the first voice is chosen** in the first-run picker, in that voice's speech language (fallback `en` if there's no seed file). If the user leaves the first-run picker without choosing (system back), the system voice is in use, so seed with the UI language then too: the app is never left without lists.
- Every language in the bundled `assets/catalog.json` must have a seed file (unit test), so the `en` fallback never applies to curated voices.
- **Switching later to a voice in another language never touches existing lists.** If no list with that `seedLanguage` exists yet and a seed file exists for it, ask once: "Hozzáadjam a(z) <nyelv> alapértelmezett listákat?" ("Add the default <language> lists?"). Yes = append that seed's lists after the existing ones. No = remember the language (`shared_preferences`, `declinedSeedLanguages`) and don't ask again. Old-language lists stay; the user can delete them.
- Sentences the user typed in another language are their content: no detection, no warnings.
```json
{ "lists": [ { "seedKey": "everyday", "title": "Alap", "kind": "everyday", "pinned": true, "color": "blue",
               "sentences": [ { "seedKey": "water", "text": "Kérek vizet!" } ] },
             { "seedKey": "alarm", "title": "Riasztás", "kind": "everyday", "pinned": true, "color": "red",
               "sentences": [ { "seedKey": "emergency", "text": "Vészhelyzet!", "sound": "siren", "alarm": true } ] } ] }
```

Restoring defaults is **non-destructive**: it only re-adds what's missing, never deletes or changes anything (so recordings, user-added and user-edited sentences are always safe).
- Per list ("Alapértelmezett mondatok visszaállítása"): re-insert the seed sentences whose `seedKey` isn't in the list anymore, at their seed position, from **that list's own `seedLanguage`** seed. An edited seed sentence keeps its `seedKey`, so it's not duplicated.
- Lists ("Alapértelmezett listák visszaállítása"): re-create seed lists of the **current speech language** whose `(seedLanguage, seedKey)` is missing, with their seed sentences. Deleted lists of other languages are not brought back (they're only restorable while a voice of that language is selected).

History: every spoken text (row tap or free text) goes in, except alarm rows (see "Alarm") and except that tapping a row while the history list itself is shown changes nothing (so the list never jumps under the finger); the same normalized text moves to the top instead of duplicating; capped at 30 (a constant, e.g. `historyCap`; nobody scrolls further than that instead of retyping), oldest dropped first, with no exceptions. History rows are their own `sentences` rows, so dropping one never touches a sentence in a permanent list. A recording only counts as kept if it is attached to a sentence in a non-history list. History rows carry the `recordingPath` of the row that was spoken, so re-tapping from history plays the same voice. A recording file may only be deleted when no remaining `sentences` row references it (see "Message banking").

## Voices
- **Voice picker (decided 2026-11-03):** a language selector at the top ("Nyelv: Magyar ▾", a full-width button opening a list of large rows, not a `DropdownButton`), hidden when the catalog has only one language. It defaults to the selected voice's language (first run: the UI language) and only filters the list; the speech language changes only when a voice is picked. Below it, for the chosen language: an "Android alapértelmezett" row, then that language's catalog voices. The system row's state comes from Android's TTS: installed → selectable; supported but voice data missing → hint + button to Android's TTS settings, re-checked on app resume; not supported → hidden (except for the UI language, where it stays as a hint so the app never looks voiceless). The system voice is only offered for catalog languages (each has a seed and a sample sentence).
- `Voice` (id, language, gender, label, kind) + `VoiceEngine` interface (`load`, `synthesizeToWav`, `dispose`). Everything above this layer (UI, sentence lists, history) only sees `VoiceEngine` and WAV paths.
- `PiperEngine`: sherpa-onnx, loads an installed voice dir. `SystemEngine`: Android TTS via `flutter_tts`, also writes WAV files so playback is uniform.
- `catalog.dart`: remote catalog JSON (one URL constant) → bundled `assets/catalog.json` fallback. Only catalog voices can be downloaded. Skips unknown `schemaVersion` and entries with a newer `minAppVersion`.
- `voice_installer.dart`: download to temp → verify sha256 → extract in a background isolate → move into place. Nothing half-installed ever appears.

## Sentence lists (UI model, decided 2026-11-02)
There are no tiles. Everything speakable is a **sentence list**:
- `SentenceList { id, title, kind: everyday | conversation | history, pinned, layout: rows | grid, sentences[] }`, `Sentence { id, text, recordingPath?, soundKey?, alarm, said }`.
- The preloaded everyday phrases are one `everyday` list (per-locale data). Users add their own lists ("Orvos", "Éjszaka"); these replace Cboard-style folders.
- A **prepared conversation** is a `conversation` list: sentences track `said`, and a "Következő" button speaks the next unsaid one.
- **History** is an automatic `history` list (newest first, capped); any sentence in it can be spoken again or saved to another list.
- Message banking attaches a recording to any `Sentence`; playback uses the recording instead of TTS.
- An **alarm** row is any sentence with `alarm = true` (see "Alarm").
- v1 layout: rows only (prepared sentences are long and would be cut off in a grid). `grid` for short everyday phrases later, if users ask for it.

Main screen (speaking mode):
```
┌──────────────────────────────┐
│ [Alap] [Kati, holnap] [▾]    │  pinned list chips + expand button
├──────────────────────────────┤
│ Ki kéne cserélni a villany…  │  big rows, tap = speak
│ Légyszi vegyetek trappistát! │  (said = greyed out, still tappable)
│ Mi újság a suliban?          │
│           [ Következő ▶ ]    │  conversation lists only
├──────────────────────────────┤
│ [free text…………  ✕] [Mondom]   │  always visible
└──────────────────────────────┘
```

Interaction rules (the user may have weak, slow or shaky hands):
- **One tap = one fixed meaning.** Tapping a sentence always speaks it; tapping a chip always switches lists. Nothing on the speaking screen is editable.
  - **The one exception: the one-shot load button** (left of the free-text field). It changes the meaning of exactly the next row tap (append the sentence to the free-text field instead of speaking), with strong cues (active button, banner with ✕, rows with a primary-color border and a ↓ icon), then turns itself off. It is also cancelled by the button, the banner's ✕, switching lists, Mondom, or the app going to the background. Loading doesn't speak, add to history or set `said`.
  - Why not a toggle: a mode left on by accident would make a tap silent in an urgent moment.
  - Rejected alternatives: long-press (slow ALS fingers exceed the long-press time, so a tap meant to speak would load instead; also undiscoverable); a per-row icon (second small target next to the big one, mis-taps); swipe (unreliable with shaky hands, conflicts with scrolling); suggestions above the keyboard (too crowded next to the keyboard's own suggestion row).
- **No layout shifts under the finger.** Sections don't expand on tap. Layout only changes through a dedicated button.
- **Chips: pinned lists only** (e.g. Alap, the current conversation, Előzmények). Switching between them is one tap, which matters mid-conversation ("Kérek vizet!" from Alap, then back to the conversation). The **▾** button expands the chip row into a large grid of all lists over the sentence area; picking one collapses it and shows that list (as a temporary chip if it isn't pinned). Lists can be pinned/unpinned.
- The app opens on the last used list, so a conversation prepared in the evening is already open the next day.
- The free-text field is always visible. Focusing it brings up the keyboard (which takes the space); closing the keyboard gives the space back to the list. No extra code needed.

List colors (decided 2026-11-03): each list has a color from a small fixed palette, stored as a palette key (not ARGB, so tones can be tuned for contrast and a dark theme without touching data). The chip, the ▾ grid tile and every sentence row of that list are tinted with it, so the user always sees which list they're in. Color is never the only cue: the selected chip also has a thick border, and history is always neutral grey. All tones must keep row text at WCAG AA contrast. New lists get the next unused color; the user can change it in the lists overview (⋮ → Szín).

Settings and editing (decided 2026-11-04): the speaking screen's app bar has a ☰ button (left) opening a **drawer**, opened only by that button, no edge swipe (rows: "Listák" → lists overview, "Beállítások" → small sound settings screen (speech boost switch, alarm volume; later speech speed), "Hang és nyelv" → voice picker; later About last). Editing is never a mode on the speaking screen and has no one-tap entry from it: editing is rare and done without time pressure, while a stray tap during a conversation must never leave the user on a screen where taps don't speak (same reasoning as the one-shot builder button, T19a). Two taps away (☰ → Listák) is fine for something done the evening before. List-level actions (create with kind, rename, pin, reorder, delete, color, restore defaults) live in the lists overview; the per-list editor is only for sentences.

Editing screens (used with no time pressure, e.g. the evening before a visit):
- One row per sentence (not one big text box: rows keep sentence ids, so recordings and `said` survive edits). Tap to edit, drag to reorder, delete, later record message-banking audio. An "add" field at the bottom: each non-empty line becomes one row. No splitting on punctuation (decided 2026-11-04): it was error-prone with Hungarian ordinals, dates and abbreviations, and a row may deliberately hold several sentences spoken in one tap ("Vegyetek sütit! Tegnap csináltuk."). A "row" is whatever the user wants said at once, not a grammatical sentence.
- From any list or history: copy or move a sentence to another list (one per-row ⋮ sheet, same everywhere). There is no "save free text" button on the speaking screen: spoken free text is in history, and is saved from there.
- Conversation lists: "reset" (clear `said`) for reuse; carry unsaid sentences over to the next conversation.

## Speech speed (T40, 2026-11-14)
Stored per voice in `shared_preferences` (`speechSpeed:<voiceId>`, default 1.0, range 0.7-1.3; see `lib/speech/speech_speed.dart`). `Speaker` reads it on each utterance, passes it to `VoiceEngine.synthesizeToWav(speed:)` and includes it in the replay key, so a speed change re-synthesizes. No model reload is needed.
- Piper: `generate(speed:)` (the configured `lengthScale` 1.2 stays the baseline).
- System TTS: `setSpeechRate(speed / 2)` before `synthesizeToFile` (flutter_tts maps 0.5 to Android's normal rate). Not verified on a device that it affects `synthesizeToFile`: check in T44.
- ElevenLabs: `voice_settings.speed`, clamped to 0.7-1.2, and part of the cache key. Omitted for `eleven_v3` (support unconfirmed; the official docs disagree). The fallback engine speaks at the fallback voice's own stored speed.
- Recordings and built-in sounds are not time-stretched.

## Loudness (T28, 2026-11-08)
`lib/speech/loudness.dart`, applied to Piper output (`boostLoudness`) and system-TTS WAVs (`boostWavFile`) when Hangosítás is on. Chain: (1) 2nd-order Butterworth high-pass at 120 Hz (`speechHighPassHz`): phone speakers can't play it, it only eats headroom; (2) peak-normalize + `speechGainDb`; (3) look-ahead limiter `limitPeaks` (~5 ms look-ahead, needed gain = sliding-window minimum, smoothed by a 5 ms moving average so it never exceeds the needed gain, ~80 ms release, final clamp to `speechCeilingDb`). The earlier per-sample `tanh` waveshaper bent every sample separately and so made harmonic distortion ("overdriven speakers"); the limiter scales whole stretches of the waveform instead. All time constants derive from the sample rate. No expander: it would pump breathing noise. Trade-off: a true limiter is a little less loud than the tanh on peaky voices (it can't win level by squashing peaks).

## Alarm (decided 2026-11-05)
Replaces the planned bell button and the 112/SMS emergency feature (dropped, see `docs/TODO.md` "Emergency"). No new button on the speaking screen: alarms are rows in a normal list.
- **Two independent row properties.** *What plays*: `recordingPath` (message banking, later) > `soundKey` (built-in sound) > TTS of the text. *How it plays*: `alarm` flag. So a built-in siren, a typed "Segítség!" and (later) an own recording can each be an alarm, and a bell can also be a non-alarm row.
- **Alarm playback**: Android alarm audio usage (own stream, gets through Do Not Disturb), at the volume from the setting (below). Not added to history. Builder load (T19a) still loads the row's text; `said` works as for any row.
- **Built-in sounds** (`lib/speech/sounds.dart`): a const table `soundKey → (asset, loops)`, e.g. `siren` loops, `bell` and `horn` play once. Looping is a property of the sound, not the row. A looping sound stops by itself after **2 minutes** (`alarmLoopLimit`) as a safety net. Sound files are generated by our own script (no third-party audio, no license question). An unknown `soundKey` (e.g. from a newer seed) falls back to TTS of the text.
- **Stopping**: while an alarm plays, a large **"Leállítás"** button takes the Következő spot (shown in every list kind). Tapping any row, Mondom, or Leállítás stops it; tapping the same row again restarts it (same as replay).
- **Row look** (decided 2026-11-05): on the speaking screen, only alarm rows are marked: a leading megaphone icon, white in a filled red circle (shape + color, so not color-only), whatever plays (sound, recording or TTS). Non-alarm rows show nothing extra even if they have a sound or recording: with message banking most rows will have one, so a marker would be noise. The list editor shows the details: a leading icon for what plays (recording → mic, built-in sound → its icon) plus the same alarm badge.
- **Seed**: a "Riasztás" list per language, `everyday` kind, pinned, `red`, last chip: "Vészhelyzet!" (siren), "Gyere ide!" (bell), "Figyelj rám!" (horn). Existing installs get it via "Alapértelmezett listák visszaállítása".
- **Volume setting** (section "Riasztás" of the Beállítások screen, `shared_preferences`): "A telefon ébresztési hangereje" (play at the current alarm volume) or "Saját hangerő" with a slider (default: maximum) and a test button. Saját hangerő: before playing, save the current alarm-stream level to `shared_preferences` (only if no saved level exists yet), set the stream to the slider level, and restore the saved level when playback ends or is stopped, but only if the stream is still at the level we set (if the user pressed the volume buttons meanwhile, keep their choice). On app start, if a saved level is still there (the app was killed mid-alarm), restore it the same way. Native side: a small `AudioManager.setStreamVolume(STREAM_ALARM, …)` channel in `MainActivity.kt` (no permission needed).
- Later: choose a row's built-in sound in the editor.

## Message banking (decided 2026-11-08)
Record your own voice for any sentence; it plays instead of TTS. Often made in the window before speech is lost, so **a recording is irreplaceable**: every rule below favors keeping it.
- **What plays**: `recordingPath` > `soundKey` > TTS (see "Alarm"). A recording works without a loaded voice and offline. A missing or unreadable file falls through to sound/TTS, so a tap is never silent.
- **Files**: `<appSupport>/recordings/<unique>.wav`, 44.1 kHz mono 16-bit (lossless, and usable later for voice banking). `recordingPath` stores the **file name only**, so a restored backup or a changed app directory doesn't break it. Copies of a row share the file.
- **Originals are never modified.** Cleanup happens on playback (`prepareRecording`: trim clicks and silence, high-pass, normalize speech level, peak limit), into a temp WAV, so it can be improved later and old recordings benefit. No compression or expander: it would raise breathing and room noise. Not tied to the Hangosítás switch.
- **One deletion path**: rows just stop referencing a file (delete, re-record, history cap, list delete). An app-start `sweep` removes files no row references, skipping files under 24 h old (a save in progress) and doing nothing at all if no row references any recording (a lost or reset DB must not wipe the files). This also keeps the Visszavonás snackbar working after a delete.
- **Recording UI**: one screen for a single row or a whole list (only rows with no recording and no built-in sound). Tap to start, tap to stop, never press-and-hold. The new take replaces the old one only on Mentés. It's reached only from the list editor; the speaking screen stays unchanged, and shows no marker for recorded rows (see "Alarm", row look).
- **Editing the text** of a recorded row asks whether to keep the recording, since it still says the old words.
- **Backup**: an explicit zip through Android's file picker (T33). Import only adds, never overwrites. No accounts: the user picks where it goes.
- **Generated recordings** (decided 2026-11-14, see "ElevenLabs voice" → "Generating a list's recordings"): a row's recording can also be ElevenLabs output saved as a normal recording (`recordingGenerated = true`). It plays, copies, backs up and gets swept exactly like an own recording. Differences: `prepareRecording` only normalizes the level and peak-limits (no trim/high-pass: it's already clean studio-like audio); the file is stored at the rate ElevenLabs returns (22050 Hz), not 44.1 kHz; and **never use generated recordings for voice banking** (ElevenLabs' policy bans training models on its output). `recordingGenerated` exists for that last rule and for the replace dialog; there is no other UI or precedence logic around it.

## ElevenLabs voice (decided 2026-11-13)
An optional, opt-in voice source using the **user's own** ElevenLabs account and API key (e.g. a Professional Voice Clone from the Impact Program, see `docs/TODO.md`). Mondom has no ElevenLabs account, key or server of its own. The offline defaults stay unchanged.

**No promotion in the app** (decided 2026-11-14): the app never advertises ElevenLabs. No Impact Program mention or link, no prices, plans, free offers or eligibility rules. These can change or end at any time on ElevenLabs' side. The setup screen keeps a short neutral intro (external service, needs a key and internet, the texts are sent to ElevenLabs) and links to the GitHub manual for details. Only the manual's ElevenLabs section may say, in one neutral sentence without a link, that ElevenLabs has offered free voice cloning to people with ALS, and that readers should look up the current options themselves.

API facts (checked 2026-11-13 with a free-plan key):
- **Key permissions**: needs "Text to Speech" and "Voices" (read). "User" (read) is optional and only shows remaining credits (`GET /v1/user/subscription`, e.g. `tier: free, character_count: 88, character_limit: 10000, next_character_count_reset_unix`); without it the API answers 401 with `status: missing_permissions` and the app just hides the credit line. "Voice collections" and "Models" aren't used.
- **Voices**: `GET https://api.elevenlabs.io/v2/voices?page_size=100` (header `xi-api-key`) → `voices[]` with `voice_id`, `name` (e.g. "Brian - Deep, Resonant and Comforting"), `category` (`premade`, `cloned`, `professional`, ...), `labels.gender`, `preview_url` (an English MP3, so not useful for us). A free account has 21 premade voices. **Language support belongs to the model, not the voice**: every voice speaks every language the model supports. The per-voice `verified_languages` field is no use for filtering: none of the 21 premade voices lists `hu`, yet they speak it fine. So the app lists **all** of the account's voices, by name only, and offers the ElevenLabs section only for languages in `elevenLabsLanguages`: a constant with the 32 languages of `eleven_flash_v2_5` (en, ja, zh, de, hi, fr, ko, pt, it, es, id, nl, tr, fil, pl, sv, bg, ro, ar, cs, el, fi, hr, ms, sk, da, ta, uk, ru, hu, no, vi; `eleven_v3` supports more). If the API still answers 400 `unsupported_language`, that's a fallback reason like any other. The goal is the user's **own** voice; the premade ones are there because they come free with the list. **Library (shared) voices can't be used via the API on the free plan** (402 with `detail.code` `paid_plan_required`, while `detail.status` is `payment_required`; the client checks both fields), so we don't browse the library: a paid user adds a library voice to "My voices" on the website and it shows up in this list.
- **Synthesis**: `POST /v1/text-to-speech/{voice_id}?output_format=pcm_22050`, JSON `{"text", "model_id", "language_code"}` → raw 16-bit little-endian mono PCM at 22050 Hz (`content-type: audio/pcm`). We add the WAV header ourselves: no MP3 decoding, and the same loudness chain as Piper applies. The `character-cost` response header says what it cost. The body must be UTF-8 (Hungarian accents).
- **Models** accepting `language_code: hu`: `eleven_flash_v2_5` (0.5 credit/char; ~0.3–0.6 s for "Kérek egy pohár vizet!" from a desktop, first call ~1.1 s) and `eleven_v3` (1 credit/char, ~1–1.4 s, more expressive). `eleven_multilingual_v2` rejects `hu` (400 `unsupported_language`). Default: flash v2.5; a "Kifejezőbb hang" switch selects v3.
- **Errors** are JSON `{"detail": {"status", "code", "message", ...}}`; the reason can be in `status` or `code`, so the client checks both. A reason is only reported ("out of credit" etc.) when the API names it; anything unrecognised is `server` ("ElevenLabs isn't available right now"). A failing request can be slow (a 402 took 10 s), hence a hard timeout.

Design:
- **Voice id** `elevenlabs:<lang>:<voiceId>`, kind `VoiceKind.elevenlabs`. Speech language = the picker language it was chosen from (same rule as the system voice); sent as `language_code`.
- **Never silent, never stuck**: `ElevenLabsEngine` wraps a **fallback engine** (an installed Piper voice or the system voice of the same language; default: the voice selected before switching to ElevenLabs). `load()` only loads the fallback, with no network. A request has a hard timeout (`elevenLabsTimeout`, 4 s, tune on the phone); any failure (no network, timeout, 401, 402/quota, 5xx, bad audio) synthesizes with the fallback instead and records why. Message-banking recordings still win over any TTS (unchanged `Speaker` priority).
- **Alarms never wait on the network**: an alarm row's TTS uses the cache or the fallback directly (`synthesizeToWav(text, urgent: true)`).
- **Cache** (unlike Piper, here it saves latency and credits, and lets the user's own voice work offline for sentences said before): `<appSupport>/elevenlabs_cache/<sha1(voiceId, model, normalized text)>.wav`, unboosted; Hangosítás is applied when copying it to the temp WAV that gets played (the speaker deletes temp WAVs, so it must never get a cache path). Capped at 100 MB, oldest-used first (touch the file on a hit). Not in the backup zip. Removing the key clears it. The cache is **purely disposable**: anything the user wants to keep for good is generated into a list's recordings (below), which removing the key, a lapsed subscription or eviction never touches.
- **Generating a list's recordings** (decided 2026-11-14, replaces the earlier "pre-cache a list" idea). Use case: clone your voice at ElevenLabs (e.g. through the Impact Program, from old recordings if speech is already gone, or 1–2 min of reading if it's still there; much easier than recording hundreds of sentences one by one with bulbar ALS), generate every list, and the app speaks those rows in your voice offline, forever, independent of the key, the subscription, the selected voice, the speed or the model.
  - **Offered wherever message banking is** (only while a key is set; the user picks which of the account's voices, preselected: the current ElevenLabs voice), so a generated recording is just another way to fill a row's recording:
    - Row ⋮ sheet in the list editor (not history): "ElevenLabs-hangon mentés" next to "Saját hang felvétele" / "Új felvétel". It opens the recording screen in a generate mode: the row is synthesized, then shown in the usual **Review** state (listen, Mentés, "Újra" regenerates; a cache hit is free). Same save/discard rules as an own take.
    - List editor app bar, next to the mic button: a cloud button for the whole list (bulk run, below). No per-row review here: listening is done by tapping rows afterwards; a bad one is fixed from its ⋮ sheet.
  - Generating means "I want this voice for these rows": it fills every row that has no built-in sound (`soundKey`), **replacing earlier generated recordings**. If some rows have an **own** recording (`recordingGenerated = false`), ask once: "N mondathoz saját felvétel tartozik. Ezeket is lecseréled?" [Igen] / [Csak a többit] / [Mégse]. Own recordings are the one thing the app can't recreate, and the sweep deletes unreferenced files, so this dialog is the only guard.
  - Before starting: show the estimated cost (characters × the model's credit rate, minus rows already in the cache) and the remaining credits if known. Each row goes through the cache first, so already-said sentences cost nothing.
  - Progress with a Mégse button; rows are saved one by one (a cancel or a failure keeps what's done). Failures (offline, out of credit) stop the run and say why; the fallback voice is **never** used here (it would save the wrong voice permanently).
  - Generated with the current speed and model, unboosted (Hangosítás applies at playback, like for own recordings).
  - Editing a generated row's text: the existing "keep the recording?" question, plus "Újragenerálás" when a key is set.
  - "Generált hangok törlése" in the list editor clears `recordingPath` on the list's generated rows only.
- **Key**: stored only in `flutter_secure_storage` (Android Keystore), never in `shared_preferences`, the backup zip, logs or error messages (strip it from anything printed). Excluded from Android auto-backup, since a Keystore-encrypted value can't be decrypted after a restore on another device.
- **Status**: `Speaker` exposes whether the last utterance fell back and why. The speaking screen's app bar shows a `cloud_off` icon then (a fixed slot, so nothing shifts under the finger); tapping it says why ("Nincs internet, Imre beszél helyette." / "Elfogyott az ElevenLabs kredit." / "Az ElevenLabs kulcs nem érvényes.").
- **Privacy**: the text of every ElevenLabs utterance goes to ElevenLabs' servers and appears in the user's ElevenLabs history. Say so on the setup screen; the privacy policy (before release) must mention it.

Legal (checked 2026-11-14 against ElevenLabs' Terms of Use and Prohibited Use Policy; not a lawyer's opinion):
- **No partnership needed** as long as Mondom stays a plain client of the user's own account. The policy bans resellers and proxies ("a client, wrapper, or proxy that gives anyone else access… outside the terms that apply", making the services available to others "on terms more permissive than those that apply to you"). So: **never ship a key, never route requests through a server of ours**, and the key stays on the device.
- **Caching is fine, with no time limit**: output belongs to the user (Terms §4(c)(ii)), and neither document restricts storing it. The 100 MB cap is a storage choice, not a legal one. Keeping generated recordings permanently is fine for the same reason. Never put cached output or generated recordings into any dataset (the policy bans using output to train competing models).
- **Name, not branding**: refer to it descriptively ("ElevenLabs hang (saját fiók)"), with no ElevenLabs logo or look-alike UI and nothing implying endorsement. About carries a trademark / non-affiliation line (T41).
- Free-plan users may only use it non-commercially (personal speech is fine), and voice clones need the speaker's consent. Both are the user's obligations under their own account, not Mondom's.
- No ElevenLabs code is bundled (plain HTTP via `http`), so it adds nothing to the license list in About and causes no GPL-3.0 conflict.
